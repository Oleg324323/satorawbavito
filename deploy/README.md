# Satorna на собственном VPS

Это отдельная production-конфигурация. `backend/docker-compose.yml` остаётся конфигурацией разработки — не используйте её для публичного сервера.

## Что входит

- Caddy: HTTPS, статический frontend, SPA-маршруты и прокси `/api/*` + `/health/*` в FastAPI.
- FastAPI, Celery worker и beat, PostgreSQL 16, Redis 7.
- Новая PostgreSQL-база, миграции Alembic; локальные SQLite, пользователи, cookies, чаты и файлы заказов **не импортируются**.
- Отдельные DB-роли: `satorna_admin` только для миграций/инициализации; приложение работает как `satorna` без superuser и BYPASSRLS. Пароль администратора не передаётся API/worker/beat.
- Приватный постоянный volume ключей шифрования. API/worker/beat подключают его read-only.
- ZIP обоих расширений в `/downloads/`; при сборке Avito-bridge разрешает точный домен вашей установки, WB получает этот домен по умолчанию. URL WB остаётся изменяемым в popup.

## Первая установка

Нужны Docker Engine + Compose v2, свободные 80/443, домен с A-записью на VPS. Стек предназначен для **новой установки**, не для подмены ролей/volumes существующей БД. Не публикуйте порт PostgreSQL, Redis или API напрямую. Для комфортной сборки TypeScript нужен запас RAM; на малом VPS предпочтительнее собрать образы на CI/отдельной машине и перенести их.

1. Склонируйте эту release-ветку на VPS. Скопируйте `deploy/.env.example` в `deploy/.env`, выставьте файлу права `600`.
2. Задайте `SATORNA_DOMAIN` — только ваш hostname, без `https://` и пути. Сгенерируйте **три разных** случайных значения для `POSTGRES_PASSWORD`, `POSTGRES_ADMIN_PASSWORD` и `VELLA_AUTH_SECRET`. Для паролей PostgreSQL используйте не менее 32 случайных hex-символов, чтобы URL подключения не требовал кодирования. Значения не коммитить.
3. Проверьте `docker compose --env-file deploy/.env -f deploy/compose.yml config --quiet`.
4. Запустите `docker compose --env-file deploy/.env -f deploy/compose.yml up -d --build`. Миграции и инициализация ключа/ограниченной роли выполняются до API.
5. Проверьте `https://ВАШ-ДОМЕН/health/ready` и `docker compose --env-file deploy/.env -f deploy/compose.yml ps`. Worker/beat отдельно: readiness не подтверждает их работу; проверьте Celery `inspect ping` и состояние beat.
6. Зарегистрируйте собственную компанию. Production не создаёт тестовые аккаунты и не переходит на in-memory авторизацию при отказе БД. Подключите WB/Авито в платформе заново: локальные подключения не переносятся.

Цена, отправка сообщений/ответов и автоматическое применение цен выключены по умолчанию. Не включайте эти переключатели без отдельной проверки прав и поведения с вашими провайдерскими аккаунтами. Расширения выполняют сбор в пользовательском Chrome, не на VPS; авторизацию и проверки Avito/WB пользователь проходит в своём браузере.

## OpenAI

Размеры из чатов Авито распознаются алгоритмом без OpenAI и API-ключа. Неоднозначные ответы требуют проверки человеком; размер из описания не подставляется вместо выбора покупателя.

В платформе: **Настройки → Профиль → OpenAI · поля Авито**. Ключ нужен для необязательного извлечения цвета и артикула. Администратор интеграций вставляет ключ и нажимает «Сохранить ключ». Он хранится зашифрованным, привязан к компании; API возвращает только состояние, не сам ключ. Сохранение не проверяет доступность OpenAI и не запускает платный запрос.

`OPENAI_API_KEY` в приватном `deploy/.env` остаётся необязательным серверным fallback для Авито и настройкой существующих других AI-функций. Ключ компании имеет приоритет для необязательных AI-полей Авито. Удаление ключа компании не удаляет fallback в `.env`. macOS Keychain/локальный `.env.avito-ai` на Linux/VPS не используются. Ошибка расшифровки не переключает запрос незаметно на другой платный ключ; алгоритмический разбор размеров продолжает работать.

## Chrome-расширения

- **WB:** скачайте `/downloads/satorna-wb-prices-extension.zip`, распакуйте и загрузите папку через `chrome://extensions` → «Загрузить распакованное расширение». В профиле платформы создайте отдельный токен расширения для нужного WB-кабинета. В popup укажите адрес backend, например `https://ВАШ-ДОМЕН` (без `/api`), вставьте токен, разрешите доступ к этому домену и проверьте подключение. Смена сервера требует остановить сбор и явно вставить токен нового сервера; старый токен/прогресс не переносится автоматически. Legacy-токены остаются привязаны к прежнему серверу даже при обновлении пакета с новым default. LOCAL-пакет допускает только loopback, не production.
- **Авито:** скачайте `/downloads/satorna-avito-orders-extension.zip` **с вашей VPS-платформы**. Его manifest содержит ваш точный домен для связи с листом подбора. В настройках расширения задайте тот же origin платформы и действующий токен входа. «Собрать всё» сохраняет снимки через backend; формирование листа проверяет полноту и свежесть. CAPTCHA/ограничения провайдера не обходятся; неполный сбор остаётся неполным.

При смене домена: измените DNS + `SATORNA_DOMAIN`, пересоберите web, обновите Avito-пакет из нового `/downloads/`, сохраните адреса расширений заново. WB-код редактировать не нужно. Универсальные GitHub ZIP используют прежние defaults; для произвольного VPS-домена пакеты создаются автоматически web-сборкой. Отдельная ручная упаковка: `node deploy/package-extensions.mjs --origin=https://ВАШ-ДОМЕН`.

## Проверка взаимодействия

Workflow `VPS build and extension integration` выполняет сборку всего frontend/образов, миграции пустой PostgreSQL, старт API/worker/beat, регистрацию, профиль, encrypted-key HTTP и Caddy-прокси/SPA/ZIP. Контрактные тесты исполняют настоящий WB-worker и Авито chat-loader с синтетическим транспортом через реальный HTTP-контракт, временную БД и platform/read/export endpoints. Это **не** подтверждение реальной авторизованной сессии WB/Авито на неизвестном VPS, DNS/TLS или доступа нового OpenAI-ключа к провайдеру.

После установки выполните один реальный сбор с вашим Chrome и проверьте подтверждение сохранения и соответствующие строки на платформе. Только после этого включайте нужные автоматические бизнес-операции.

## Резервные копии и обновление

Сохраняйте PostgreSQL, volume `credential_keys` и приватный `.env` раздельно и защищённо. Без того же keyring encrypted-ключи восстановленной базы не расшифруются. Не пересоздавайте ключ `1` при обновлении. `init-keyring.py` никогда не заменяет существующий ключ.

Обновление: резервная копия → получение новой версии → `up -d --build` → readiness + worker/beat + контрольный сбор. Для остановки используйте `down` **без `-v`**: удаление volumes уничтожает базу/ключи. CI удаляет только свои одноразовые тестовые volumes, не production.

## Текущий production-вход comcookie.store

Приложение обслуживается напрямую по `https://app.comcookie.store`: A-запись `app` указывает на VPS `109.69.22.214`, Nginx отдаёт frontend и проксирует API/health в локальный контейнер. Конфигурация — `deploy/nginx-app.conf`. Сертификат Let's Encrypt выпускается через webroot `/var/www/satorna-acme`; HTTP challenge остаётся доступным при продлении. В новом origin потребуется войти в существующий аккаунт.

`comcookie.store` и `www` сохраняют Vercel A-адреса `216.198.79.1` и `64.29.17.1`, TTL 3600. Vercel перенаправляет страницы, JS/CSS и ZIP на `app.comcookie.store` временным HTTP 307, сохраняя путь. Большие файлы и API приложения не проходят через CDN, где воспроизводился обрыв после примерно 30–36 КБ. Для ранее установленных расширений `/api/*` и `/health/*` сохраняют HTTPS-прокси на `api.elfprint-system.ru:8443` без редиректа. Build Output API конфигурация шлюза — `deploy/vercel-gateway.json`; static-пакет приложения на Vercel не загружается.

Avito 0.2.20 использует `https://app.comcookie.store`, мигрирует прежние production-адреса и содержит bridge для домена приложения. Пакеты для альтернативных API-входов формируются с их точным origin. Разбор размеров остаётся алгоритмическим, без AI.

После публикации проверяйте вход через основной домен и приложение в браузере, сертификат, полную передачу больших JS/CSS/ZIP, авторизованный API и refresh сессии. Отдельно проверяйте текущую сеть с VPN и прямое подключение; запрос с VPS или синтетический CI не подтверждает доступность из пользовательской сети. Затем выполните реальный авторизованный сбор Avito в пользовательском Chrome и сверьте сообщения, размеры, причины review и XLSX.
